# ASLR과 오프셋의 한계

## 핵심 요약
**ASLR (Address Space Layout Randomization)**은 메모리 침러(해커)를 막기 위해 프로그램이 실행될 때마다 스택, 힙, 라이브러리의 시작 주소(Base Address)를 무작위로 섞어버리는 방어 기법이다.

하지만 ASLR에는 구조적인 치명적 약점이 존재한다.
건물의 위치(시작 주소)는 매번 바뀌지만, **건물 내부의 방 구조(상대적 거리, Offset)는 절대 변하지 않는다.**

## Information Leak (정보 유출) 공격
해커들은 ASLR을 무력화하기 위해 버퍼 오버플로우나 포맷 스트링 버그를 이용해 메모리의 특정 주소(끄나풀) 단 하나만을 화면에 출력(Leak)되도록 유도한다.

1. 특정 함수의 주소 하나를 알아낸다. (예: `0x5000`)
2. 해커는 사전에 자신의 컴퓨터에서 로컬로 디버깅하며 오프셋을 계산해 두었다. (예: 해당 함수로부터 카나리까지의 오프셋은 무조건 `+150 Bytes`이다.)
3. `0x5000 + 150 = 0x5150`. 해커는 유출된 베이스 주소에 고정된 오프셋을 더하여, ASLR이 섞어버린 전체 메모리 지도를 완벽하게 역산해 낸다.

이 원리 때문에 ASLR 환경에서도 카나리(Stack Canary)를 읽어내거나 ROP(Return-Oriented Programming) 공격을 수행할 수 있게 된다.
